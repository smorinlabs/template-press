### (b) Git-clean remedy

`-X` is the correct selector; `-x` is not. `-x` would also delete non-ignored untracked files that the press deliberately includes in its authorized inventory. [inventory.py:919](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/inventory.py:919>)

The proposed command is nevertheless too broad and incomplete:

- `git clean -fdX -- <prefix>` removes every path Git currently considers ignored below the prefix, not merely the blockers listed by the refusal. Ignored credentials, local configuration, or operator data may disappear.
- It cannot repair an unignored empty directory or a non-ignored node created after snapshot capture.
- A raw Git invocation may use global/system ignore configuration that the press neutralizes and pins during inventory, so its deletion set can exceed the press’s blocker set. [inventory.py:140](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/inventory.py:140>)
- Nested `.gitignore` rules are correctly interpreted by Git. Conversely, a single `-f` does not authorize deleting nested repositories; do not “fix” that by recommending `-ff`. Embedded repositories receive special inventory treatment and require manual disposition. [inventory.py:864](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/inventory.py:864>)
- A gitlink is the earlier immovable-boundary refusal, not a cleanable blocker.
- A direct symlink rename is a no-follow leaf and should already be inventoried; cleanup code must never traverse a symlink prefix. [substitutions.py:476](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/substitutions.py:476>)
- A shell string is not portable to Windows and can mis-handle spaces, newlines, leading dashes, or Git pathspec magic.

Show target-aware, literal-pathspec argv conceptually:

```text
preview argv: ["git", "--literal-pathspecs", "-C", TARGET, "clean", "-ndX", "--", PREFIX]
remove argv:  ["git", "--literal-pathspecs", "-C", TARGET, "clean", "-fdX", "--", PREFIX]
```

Label the remove form “destructive, broader than the reported blockers; run only if the preview contains exclusively disposable paths.” It must remain operator-executed and must not be emitted as an automatically safe remedy.

### (c) Machine-readable refusal

Use a typed error, not a stable ad-hoc line. Filenames may contain newlines or undecodable POSIX bytes, making an unescaped line protocol unsafe.

The producer should raise a `SafetyError` subclass carrying:

```text
code, source_prefix, findings[{kind, path}], total, truncated, phase
```

The CLI should serialize it under an explicit structured-diagnostics flag while retaining exit code `2`. Exit `2` already means a precondition/configuration refusal with nothing written; introducing a distinct process code would break the documented automation contract unnecessarily. ### Automation boundary

Accept engine-side diagnosis, not engine-side deletion:

- Exit `2` with stable `error.code = "rename_closure_unauthorized"`.
- Return the sorted typed findings and preview argv.
- Let the wrapper display the Git preview, obtain explicit confirmation, perform external cleanup, and rerun planning from a fresh snapshot.

Do not add `press clean` as part of this fix. Gitignored means “not tracked,” not “disposable,” and ignored data has no Git recovery path. Existing declared deletion is allowed only for clean, tracked regular files precisely because Git provides recovery. [remove.py:50](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/remove.py:50>)

A future `press clean` would need a separate accepted destructive-operation design: preview by default, immutable manifest binding, exact-path deletion rather than prefix-wide cleaning, immediate revalidation, no-follow removal, and refusal for gitlinks, symlinks, embedded repositories, non-ignored empty directories, or changed ignore inputs. That is disproportionate to this diagnostic fix.

I agree with the other rejected alternatives. Carrying, skipping, or engine-deleting ignored nodes breaks the authorized-closure/undo model; default-authorized globs turn cache policy into hidden movement authority; and `--clean-ignored` makes destructive behavior part of rebrand. Skipping a child also cannot coexist with the atomic whole-prefix move: the filesystem rename moves the directory as one object. [safety.py:704](</Users/stevemorin/c/template-press-pr90-fork-press-improve-g2p/src/template_press/rebrand/safety.py:704>)
